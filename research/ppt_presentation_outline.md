## Slide 4. 해결 아키텍처 — 결정론적 코드와 LLM의 4단계 역할 분리 — `[2:15 – 3:15]`

### 화면 레이아웃 & 시각화 가이드
- **핵심 철학 배너:** `"소형 AI에게 바이너리 파일 해독과 부가세 곱셈까지 맡기지 않는다" (Decoupled Hybrid Architecture)`
- **4단계 수평 플로우 다이어그램:**
  - **Step 1. 순수 코드 파서 (`0 토큰`)**
    - `pipeline/hwp_parser.py` & `docs/hwp_browser_parser.js`
    - `.hwp` (OLE2 FAT/MiniFAT + zlib + HWPTAG 67) / `.hwpx` (OWPML XML 표 추출) 유료 한컴 라이선스 없이 100% 해독
  - **Step 2. AI 의미 추출 (`BAZE gpt-6.1-terra` ↔ Local `EXAONE 3.5` / `Qwen 2.5`)**
    - 유일한 LLM 구간 (~3,000 입력 → ~800 출력 토큰)
    - OpenAI 호환 API + **JSON Schema 검증 실패 시 최대 3회 에러 역주입 자동 재시도**(`--max-retries 3`)
  - **Step 3. 결정론적 가드레일 (`산술 오류 0%`)**
    - `normalize_and_crosscheck()`: 수량×단가, VAT(10%), 3-Way(`견적↔발주↔검수`) 일치 여부 코드로 강제 검증
  - **Step 4. 단일 원천 4종 서식 생성 & Human-in-the-Loop**
    - 1번 품목 수량·단가 수정 시 4종 한국형 A4 서식 즉시 동시 갱신 + 실무 리스크 경고 체크포인트
- **하단 3대 비교표 (기존 사내 DB · 일반 사내 RAG LLM vs 본 시스템):**
  - `기존 사내 DB/ERP`: 사내 확정 데이터 저장(System of Record) — 외부 `.hwp` 해독 불가(사람이 4번 수기 입력)
  - `일반 사내 RAG LLM`: 과거 문서 Q&A 검색(Top-K 청크) — `.hwp` 표 붕괴 · 산술 환각 · 4종 서식 생성 불가
  - `본 파이프라인(Action)`: 외부 `.hwp` 무손실 파싱 + 사내 DB·RAG 단가 조회 연동 + 3-Way 산식 검증(오류 0%) + 4종 서식 일괄 생성

### 발표 대본 (약 60초)
> "저희 아키텍처의 가장 큰 차별점은 **결정론적 코드와 생성형 AI의 역할을 엄격히 분리(Decoupling)**한 것입니다.
> 기존 사내 DB나 사내 RAG 챗봇이 '과거 데이터 저장·검색'에 그친다면, 저희는 외부 `.hwp` 공고 해독부터 사내 DB 입력·서식 생성까지 이어주는 실행 파이프라인입니다. 먼저 **1단계**에서 자체 구현한 Python 및 브라우저 파서가 별도 한컴 프로그램 없이 `.hwp` 바이너리와 `.hwpx` XML 표를 토큰 0으로 분해합니다.
> **2단계**에서만 BAZE API `gpt-6.1-terra` 또는 사내 로컬 sLLM을 호출해 JSON을 뽑고 최대 3회 자동 재시도합니다.
> 그리고 **3단계**에서 `normalize_and_crosscheck` 코드가 수량×단가와 부가세 10%, 3-Way 일치를 100% 검증한 뒤, **4단계**로 4종 A4 서식을 동시 생성합니다."

## 예상 질의응답(Q&A, 3분) 방어 전략 Top 5

### Q1. "한컴오피스 API나 유료 솔루션 대신 직접 파서를 짠 이유가 무엇인가요? 표가 깨지지 않나요?"
- **핵심 답변:** 한컴 SDK는 유료 라이선스 비용과 Windows 서버 종속성이 있어, 영세 중소기업(5~30인)이나 GitHub Pages·리눅스 폐쇄망 컨테이너에 바로 배포하기 어렵습니다. 저희는 **`.hwp` 5.0(OLE2 FAT/MiniFAT + zlib + HWPTAG 67)과 `.hwpx`(KS X 6101 OWPML ZIP+XML)를 순수 Python 및 브라우저 JS로 직접 구현**해 라이선스 비용을 0원으로 낮췄습니다. 실제로 303문단·8개 표가 포함된 방위사업청 무인항공기 공고(`.hwpx`)와 54문단 방산혁신기업 공고(`.hwp`)까지 깨짐 없이 Markdown 표로 추출되는 것을 검증했습니다. *(한계 인정: 스캔 이미지로만 붙은 PDF/HWP는 OCR 전처리가 추가 필요함도 솔직히 답변)*

### Q2. "발표 중 시연한 BAZE LLM(`gpt-6.1-terra`) 외에, 진짜 폐쇄망 소형 모델(7B~14B)에서도 JSON이 제대로 나오나요?"
- **핵심 답변:** 만약 소형 모델에게 HWP 해독·세액 곱셈·서식 HTML 작성까지 모두 시키면 실패율이 높습니다. 하지만 저희 구조는 **파싱과 사칙연산(VAT 10%, 3-Way 일치 검증)을 코드로 완전히 분리**했기 때문에, sLLM은 오직 잘 정제된 텍스트에서 고정 JSON 필드만 채우면 됩니다. 또한 `baze_pipeline.py`에 에러 역주입 3회 자동 재시도(`--max-retries 3`)를 구현해 1차 실패율 15%에서도 3회 내 성공률 99.66%($1 - 0.15^3$)를 확보하도록 설계했습니다. *(솔직한 범위 명시: 본 시연에서는 BAZE API `gpt-6.1-terra`로 실물 4종 추출을 실측 검증했으며, `EXAONE 3.5`·`Qwen 2.5` 적용 수치 및 TCO는 `--base-url` 호환 아키텍처에 기반한 시나리오 설계 추정입니다.)*

### Q3. "대전 중소기업 통계에서 소상공인이 95%인데, 왜 소상공인이 아니라 정밀제조·방산·연구기자재 SME를 잡았나요?"

### Q4. "무료 배포 가능한 수준인가요, 아니면 사업화 시 수익모델/유지보수는 어떻게 되나요?"
- **핵심 답변:** 현재 코드는 오픈소스로 공개해 진입장벽을 없앴으며(중기부 조사상 SME가 가장 원하는 것이 '맞춤형 성공사례 66.3%'), 실제 기업 도입 시에는 **① 기업별 고유 사내 양식(견적·품의 템플릿) 1회 커스터마이징 셋업** 및 **② 폐쇄망 Local sLLM(`Ollama/vLLM`) 워크스테이션 패키지·유지보수 구독 모델**로 확장할 수 있습니다.

### Q5. "이미 사내 DB(ERP)가 있거나 사내 데이터를 연동한 RAG LLM 서비스가 있는 회사라면, 이 시스템이 중복되어 불필요하지 않나요?"
- **핵심 답변 (현실 통계 + 구조적 역할 차이 + 상호보완):**
  1. **도입 현실:** 대한상의 경제연구원(2026.06) 조사상 사내 맞춤형 AI 도구(사내 LLM·RAG 등)를 제공하는 **중소기업은 단 5.7%**(미제공 94.3%)이며, 한국직능연 패널 분석(2026.05)상 **100인 미만 기업 AI 활용률은 6.2%, 제조업은 5.7%**에 불과해 대다수 대전 SME에는 RAG 자체가 없습니다.
  2. **설령 사내 DB·RAG가 있어도 대체가 아닌 상호보완(Ingress/Action):**
     - **사내 DB(System of Record):** 이미 입력된 정형 데이터를 보관만 하며, 방위사업청에서 날아온 신규 `.hwp` 공고를 스스로 파싱해 4종 서식을 만들 수 없습니다.
     - **일반 사내 RAG LLM(System of Knowledge):** 사내 과거 문서를 벡터 청킹해 **질의응답(Top-K 검색)**하는 도구이지, 외부 `.hwp` OLE2/OWPML 표 전체를 무손실 구조화(Full Schema)하고 `수량×단가·VAT 10%·3-Way 대조`를 산술 오류 0%로 실행하는 트랜잭션 엔진이 아닙니다.
     - **결합 시너지:** 본 파서가 외부 `.hwp` 공고를 무손실로 해독한 뒤, 사내 DB/RAG에서 과거 납품 단가·재고·보안규정을 조회해 4종 서식을 검증·생성하고, 최종 승인된 JSON을 다시 사내 DB·RAG에 자동 적재하는 **앞·뒷단 실행 파이프라인**으로 결합됩니다.
